> **这份文档给谁用**：实现 Android 界面的 agent / 人。
> **唯一真源**是 `docs/android/mockups/` 下的静态示意：56 屏 HTML（36 常态 + 20 状态，`screens/`）
> + 明暗两套 @2x 截图（`shots/`、`shots/dark/`），样式在 `mockups/mockup.css`

> 控制面契约见 `docs/ipc.md`。

>

## 3. 外壳与导航

- **顶栏**：高 56，`grid-template-columns: 34px 1fr 34px`，左右内边距 18。
  左格是返回键（34 圆、底色 `--chip-fill`、图标 18、线宽 2.6）；中间标题 17/600 居中；
  右格留空占位，保证标题真正居中。
- **返回键只有一级**：从二级页返回上一级，不做“关闭”。
- **没有底部 tab**。抽屉从聊天页左上角汉堡打开（会话抽屉宽 310）。
- **抽屉**：搜索胶囊 52 高、圆角 26，`--fill-2` 底；分组头 15/500 `--ink-3`，
  行 50 高、圆角 14；选中行底色 `--brand-soft`、文字 `--brand`；底部账户行固定。

## 4. 设置类页面骨架

所有二级页（设置、本机、账户、备份、主机参数、数据管理…）共用同一套骨架：

```
顶栏 56
内容区 padding: 2 18 0
  分组：label（14/20，左缩进 17，下 8）+ 卡片（r16，--card）
  卡片可叠 24 间距；单独的卡（不带 label）用 30 上间距
  底部说明 12/20，--ink-4，居中
```

| 元素           | 规格                                                            |
| -------------- | --------------------------------------------------------------- |
| 行高           | 单行 **52**；带副标题 **64**                                    |
| 行内边距       | `0 17`，元素间距 14                                             |
| 行图标         | 22 × 22，线宽 **1.9**，`--text`                                  |
| 行标题         | 17 / 400（危险行为 `--danger`）                                  |
| 行副标题       | 12 / 16，`--ink-3`，单行省略                                     |
| 行右侧值       | 16 / 20，`--ink-3`，最大宽 168，右对齐、单行省略                 |
| 等宽值         | 12.5（版本号、路径、时间、地址）                                 |
| 箭头           | 18 × 18，`--ink-4`；**只有能进下一页才画**                        |
| 危险行         | 文字与图标 `--danger`；副标题保持灰                              |
| 不可用行       | 文字、图标、值全部 `--ink-4`，右侧写清原因（如“需先停止服务”）   |

**箭头语义**：进入下一层 → 画箭头；直接触发动作或弹窗 → 不画箭头（“新建备份”“添加账户”
“删除所有对话”“恢复并重启”都属于后者）。

### 5.1 按钮

| 类型        | 规格                                                                 |
| ----------- | -------------------------------------------------------------------- |
| 主按钮      | 高 48；页面底部主操作 52；**全宽胶囊 `999px`**，`--brand` 底、白字 17/600 |

| 字段标签                                  | 13/18 `--ink-3`，位于输入框上方 8            |
| 输入下方说明                              | 12/18 `--ink-3`，距输入 8                   |
| 密码占位“●”                               | 固定 11px + 字距 3；字号一跟随输入框就会又黑又重 |

### 5.3 校验错误

统一一种画法，**只在用户真的写错时出现**，不要一进页面就标红：

- 输入框加内描边 `inset 0 0 0 1.5px var(--danger)`（不改变控件尺寸，版面不跳）
- 框下一行红字 12/18，左边距 4，紧贴输入框
- 例：地址连不上、用户名带非法字符、两次密码不一致
- 服务端只回“凭据不对”时（远程登录），**两个框都标红**，并写“用户名或密码不对，再试一次。”
- 地址错时**不要**标红服务器标签：标签仍显示“已连接”，错误只在输入框

| 项       | 规格                                                             |
| -------- | ---------------------------------------------------------------- |
| 遮罩     | `rgba(0,0,0,.32)`                                                 |
| 面板     | 宽 **300**，居中，圆角 20，`--card`                               |
| 标题     | 17/600/24，上内边距 22，居中                                      |
| 正文     | 14/21，`--ink-2`，居中，上 6 下 20                                |
| 动作区   | 高 52，两等分，1px 细线分隔；默认“取消”（`--ink-2`）              |
| 破坏性   | 确认侧用红字（`--danger`），不用实心红块                          |
| 单选弹窗 | 无正文；选项行 56、左单选 22、文字 17；底部“确认”蓝字 52 高       |

弹窗正文最多两行，超过就精简文案；**不要把选项列表塞进确认框**。

### 5.5 单选、开关、滑轨

- 单选：22 圆，未选描边 1.5 `--ring`，选中描边 2 `--brand`，内点 10（整数像素，居中）
- 开关：51 × 31，轨道 `--line`，打开 `--green`；圆点 27，白色，上 2，关时左 2、开时左 22
- 滑轨：轨高 4、圆角 999、`--track`；滑块 26 白圆 + 阴影；刻度 1.5 × 12，`--tick`

### 5.6 状态卡与步骤条

状态卡用于“本机 / 远程”的当前状态：

```
卡内边距 16 17，圆角 16
状态行：圆点 10 + 状态文字 24/600 + 右侧胶囊（内置后端 / 远程 24 高、12px）
键值区：margin-top 15，间距 10，行 13/18，值等宽 12.5 右对齐
动作区：margin-top 16，按钮等高并排
```

状态圆点：运行中/已连接 = `--green`；未初始化/已停止 = `--dot-mute`；
准备中 = `--brand`；失败/断开 = `--danger`。

步骤条（只在本机初始化里用）：卡片上下留 10，行高 56，圆 22，连接线 2 × 34。

| 状态   | 画法                                     |
| ------ | ---------------------------------------- |
| 已完成 | 绿底白勾 + 后续连接线变绿                |
| 进行中 | 绿描边圆 + 绿色数字                      |
| 待办   | 灰圆环 + 灰数字 + 灰文字                 |
| 失败   | 红底白叉；后续步骤回到待办               |

**语义必须一致**：绿色 = 完成，绿圈 = 正在做这一步，灰 = 还没轮到。
不要加进度条、百分比、转圈——每一步本身就是进度。

### 5.7 首次启动

整屏只有两样东西，**作为一块整体垂直居中**：品牌鲸鱼 132（`--brand`）+ 间距 44 +
胶囊按钮 52（左右各留 18）。不贴底、不列服务器、不放字标。
点按钮进入“切换或添加服务器”，与设置里的入口复用同一屏。

## 6. 文案

- **只写用户看得见的话**。不写实现：不说 ipc、DB、进程、端口、重启服务、写盘，只说结果与动作。
- 短值不加句号（`所有者 · 共 2 个`、`需先停止服务`）；独立句子加句号（`启动后就能登录本机服务聊天。`）。
- 一行说完就一行。**弹窗已经把后果讲清楚的地方，页面上不再重复小字**。
- 页面上不放“解释这个功能是什么”的段落；需要解释就写进空态或错误行。
- 错误文案写“发生了什么 + 能做什么”：`连不上这个地址，检查地址和网络。`
- 不出现官方有、我们没有的入口文案（如“数据用于优化体验”“我共享的链接”）。

### 7.1 状态屏（36 屏之外的过场与异常态）

这些不是新页面，是上面某些屏的**另一个状态**，所以标题不带编号，文件名是「屏名-状态」。
实现时它们不是独立路由，而是同一屏的状态分支；示意单独出图只为把「这时候长什么样」定死。

## 8. 关键流程

**首启**：`01` → `02` → 选本机进 `03`（选远程进 `14`）。

**本机初始化**（一条链，状态不可跳过）：
`03 未初始化` →（点初始化）`04 准备中`（步骤条走 1/3、2/3）→ `06 创建本机账户`（步骤条 3/3 进行中）
→ `08 初始化完成`（三步全绿，约 1 秒）→ `09 已停止` →（点启动）`10 运行中`。
任一步失败 → `05 初始化失败`，`重试` 回到 `04`。
初始化进行中“切换或添加服务器”不出现，避免半途换服留下坏状态；
初始化本身在后端继续，退出页面不等于取消（见 `docs/android-architecture.md` §7）。

**远程**：`02` → `14 添加` →（测试通过）`16 登录` → `18 详情`；失败分别走 `15` / `17`，
断线走 `19 重连`。远程没有账户/备份/主机参数入口——那需要 SSH，App 不做。

**备份**：`22 列表` → `23 详情` → `24 恢复` 或 `25 删除`。新建备份永远在列表最上面。
备份与恢复都要求服务停止；恢复完成后自动重启服务（按钮文案“恢复并重启”就是这个意思）。

**账户角色**：只有 `成员`（只能聊天，默认选中）与 `管理员`（可以管理账户和备份）。
不提供“所有者”：能建所有者的人本身就是所有者，建完平级，风险不对等。

## 9. 明确不做的部分

- **聊天页的聊天行为照上游 `src/`**：消息流、思考过程、消息操作、断线提示都以官方实现为准。
  示意里的 `11`、`12` 只锁视觉（间距、胶囊输入、chip、抽屉），不新造交互。
- **不设底部 tab**、不做服务器市场、不做远程运维面板、不封装 SSH/SFTP。
- 远程服务器只有：地址、连接状态、登录账户、切换服务器。
- 数据管理不出现官方的“数据用于优化体验”“我共享的链接”——我们没有这些功能。
- 语言只有 系统 / 中文 / English，不复制官方 65 种清单。
- 不在页面里解释实现原理；错误只解释“发生了什么 + 怎么办”。

## 10. 暗色模式

只换 §2 表里的颜色 token，**尺寸、字号、间距、圆角一律不动**。

- 触发方式：`prefers-color-scheme: dark`（跟系统走），页面里不塞主题开关；截图时由 CDP 模拟该系统偏好
- 卡片从白变 `--card`，页面底从 `#f7f8fa` 变 `#151517`，两者必须拉开一档
- 品牌色变亮一档（`#3964fe → #5686fe`），危险色同样变亮（`#ec1313 → #f25a5a`）
- 浅色下“选中行”是淡蓝底，暗色下必须是深蓝底（`--brand-soft`），**不能留成白块**
- 绿色小胶囊文字在暗色下要换成亮绿（`--green-ink`），否则看不见
- 登录/认证页的白底走 `--bg`，不要写死白色

核对方式：`shots/` 与 `shots/dark/` 一一对应，同名成对；两边都要过一遍。

2. **暗色 36 屏对照** `shots/dark/*.png`：只变颜色，位置不移动
3. **20 个状态屏对照**（§7.1）：状态分支不是独立路由，但画出来的样子要和示意一致；
   明暗两套同上
3. 顶栏：标题真正居中（左右两格等宽），返回键 34 圆
4. 按钮：全宽一律胶囊；禁用主按钮是品牌色 45% 透明而不是灰底
5. 行：52 / 64 两档；能进下一页才有箭头；危险行文字红、副标题灰
6. 步骤条：绿勾 + 绿线 + 绿圈 + 灰待办四种状态语义正确，没有进度条或百分比
7. 三处红圈：地址错、登录错、用户名错——都只在“已经出错”时出现

## 12. 怎么重新生成截图（可选）

示意是纯静态 HTML，没有构建。截图用无头 Chrome 的 CDP：

```sh
node tmp/cdp.mjs <url> <out.png> 390 844   # 明色
DARK=1 node tmp/cdp.mjs <url> <out.png> 390 844   # 暗色
```

`tmp/cdp.mjs` 是本地脚手架（不入库）：它设置 390 × 844 视口、@2x、关缓存，
`DARK=1` 时把 `prefers-color-scheme` 模拟成 dark。日常改的是
`mockups/mockup.css` 与 `mockups/screens/*.html`，截图只是产物。

## 13. 实现后的回归（不是 `tmp/cdp.mjs`）

`tmp/cdp.mjs` 只用来重截示意。实现后的回归用 `scripts/shots.mjs`（入库），做法是
**同一次运行、同一个浏览器里双渲染对比**，这样即使不锁 Chrome 版本，也不会被版本漂移干扰：

1. 起一个 headless Chrome（普通 Chrome，经 `--remote-debugging-port` 控制，不锁定版本）；
2. 打开示意页 `mockups/screens/<name>.html`，按 390 × 844、`deviceScaleFactor 2` 截图；
3. 打开实现页（`pnpm build:mobile` 的产物；`scenario/` 提供固定的 fake host / fake net），同视口再截一张；
4. 两张图 diff，只报差异区域与比例；明暗各跑一遍（`Emulation.setEmulatedMedia` 模拟
   `prefers-color-scheme`，不能用 `--force-dark-mode` 代替）；
5. 真机抽检用 `chrome://inspect` 连 WebView，同一个脚本对真机截图再跑一次。

约定：

- 容差从「单屏差异 ≤ 0.5%、1px 膨胀抗锯齿、结构位置零容忍」起步，第一版按实际调；
- 英文直译造成的换行差异不计失败；
- CI 必须装 `fonts-noto-cjk`，否则中文截图全是方框；
- 基线切换见 §11：首版验收通过后，以该版本截图为准。
